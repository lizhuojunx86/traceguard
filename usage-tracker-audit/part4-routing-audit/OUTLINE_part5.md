# Part 5 — 提纲

Series A 第五篇。Part 4 的自然延伸：同一条不变量，从自己的机器扩到别人的
分发渠道。**不要现在动笔**——先发 cct issue，等几天看有没有回应，理由见文末。

## 主线

Part 4 说：我的 96 条偏差，全部来自没有模型决定的组件。

Part 5 说：**一个 30k 星的仓库分发了 423 个 agent 定义，356 个没有模型决定，
8 个根本起不来。而其中 3 个坏掉的，写下来那天是对的。**

那 3 个是全篇的支点。它们拼写完全正确，通过任何静态检查，能跑很久，然后在
某一天 Anthropic 下线 `claude-sonnet-4` 之后，无声地变成了硬报错——**没有人
改过一行代码，也没有任何东西通知作者。**

所以这篇不是"一个仓库写错了配置"。是：

> **钉住一个模型，是给你的配置设了一个你不知道到期日的保质期。**

## 结构

### 1. 开场 ~150 词

Part 4 的结论是「偏差聚集在没人做选择的地方」。那是在我自己一台机器上的
425 个决策点上测的。这篇把同一条检查指向别人分发出去的东西。

直接给形状：423 个定义，356 无决定，8 起不来，其中 3 个曾经能跑。

### 2. 普查 ~250 词

全量表（不是抽样，GitHub tree API 拿全 423 个路径，逐个取 raw，0 失败）：

```
356  无 model:            继承主线程
 48  别名（sonnet 47 / haiku 1）  跟随该档最新款
  3  精确 id              冻结在具体模型
  1  inherit              显式继承
  8  坏                   硬报错，0 token
  7  无 frontmatter       未测
```

**356 不是本篇的主角，要主动把它降级。** 它继承，而继承可能正是作者想要的；
把它写成缺陷就是 Part 3 立过的那条"不要暗示对方失职"。真正的新闻是 8。

### 3. 八个里的两类，这是核心 ~350 词

**五个：把显示名写进了 id 的位置。** `Claude Sonnet 4.5`、
`Claude Sonnet 4.5 (copilot)`。写下来那天就是坏的。可以静态检查出来。

**三个：`claude-sonnet-4`，拼写正确，曾经能跑。**

这三个是文章的支点，要给它足够的篇幅：

- 它们通过任何 linter
- 它们在 code review 里看起来完全正常
- 它们跑了不知道多久
- 然后模型退役，它们变成硬报错
- **没有 commit、没有告警、没有版本变更能标记这一刻**

对比同一仓库里 48 个写别名的：`sonnet` 解析到该档最新款。它们永远不会遇到
这件事，因为档位不退役。

**要落的那句**：一个配置字段的正确性，取决于一个不在你仓库里、不在你依赖清单
里、也没有人承诺会通知你的外部事实。

### 4. 我怎么知道的 ~200 词

七个探针，每一种拼写一个，实跑一次，从 transcript 读回实际模型。

**必须写进去的两条复现障碍**，因为它们会让别人复现失败并得出相反结论：

- `claude --version` 在我机器上报 2.1.152，实际跑的是 2.1.226。差 74 个补丁版本，
  因为 `--version` 回答的是 `PATH` 上一个陈旧安装，不是那个进程。**读
  transcript 的 `version`。**
- subagent 注册表在会话启动时快照。会话里新建的定义文件调不到，报
  `Agent type '...' not found`。不重开会话的人会以为"定义不生效"。

这一节顺带回答一个已经有四份报告的公开问题（`anthropics/claude-code` #43869
等）：**在 2.1.226 上，定义文件里的 `model:` 是生效的**，短名、全名、`inherit`
都生效，显式传参压过定义。这不等于那些报告是错的——**只等于在我测的这个版本、
这两条路径上复现不出来。**

### 5. Counterweights ~200 词

- **我在这一篇里错过两次。** 第一次：以为旧世代 id 会一起退役，
  而 `claude-sonnet-4-5` 至今在线，只有 `sonnet-4` 那一代没了。第二次：写了
  一个判读脚本，它对 `inherit` 打出 "NOT honoured"，而跑出父模型对 inherit
  正是生效——**一个给出自信错误答案的判读函数，比没有判读函数更糟。**
- **356 不是 bug。** 重复一次。
- **7 个无 frontmatter 的没测**，它们的问题是能不能被注册，不是路由到哪。
- **只测了一个版本。** 而这个行为一年内至少变过一次（内置 Explore 在 2.1.198
  解绑），所以本篇的保质期本身也是有限的——**这篇文章会以它描述的同一种方式
  过期。**

最后这条要放在 Counterweights 的最末，它是全篇的自指收尾，不要解释它。

### 6. What I would generalize

- **钉模型会腐坏，钉档位不会。** 别名跟随该档最新款；模型 id 会退役。
  如果你不是真的需要某个具体模型，别名的保质期更长。
- **正确性可以有到期日。** 一个字段今天对、明天错，而中间什么都没发生。
  静态检查抓不到，因为文件没变。
- **"曾经能跑"是一种独立的坏法**，值得和"从来没跑过"分开计数。
- **一个降级得很诚实的检查，如果降级点恰好是最自然的用法，等于没有检查。**
  （我的脚本从它自己所在目录跑，七条全打 "NO DEFINITION FILE FOUND"。）

### 7. 结尾

给可复现的东西，不给结论——同系列一贯做法。

普查是一条命令，任何人对任何 agent 目录都能跑：

```bash
for f in .claude/agents/*.md; do
  printf '%-40s %s\n' "$(basename "$f")" "$(grep -m1 '^model:' "$f" || echo '(inherits)')"
done
```

它不告诉你哪个坏了——那需要真跑一次。它告诉你**你钉的是模型还是档位**，
而这一条决定了你的配置有没有到期日。
